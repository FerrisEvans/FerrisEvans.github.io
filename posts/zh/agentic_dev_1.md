本文第一版行文于 2025 年圣诞节前，但会根据技术的发展而迭代文章的内容。如今一年已过，现在已经临近 2026 年的圣诞节。在这一年中，AI Agent 的开发已经取得了非常大进步。于是我决定把原本一篇文章内讲的东西扩展成一个系列，而作为系列第一篇文章，本文不会涉及太多技术细节，更偏向于引领刚从事 AI Agent 开发和设计这个领域的小伙伴们找到一个入门的方向和指引。

从 Agent 开发尚未成为一个真正的岗位出现在招聘软件上之前直到今天，虽然从具体实现细节上复杂了很多，但好在总体架构清晰。各种技术就像枝叶，生长在架构这根树干上。虽然我们面对的已经不是简单的自动化系统，而是一整套复杂的自主系统，但是如果采用渐进式，由浅入深、由易到难的方式来学习，过程也不是很陡峭。

> [!NOTE]
> 我们可以来粗浅的看一下。
> 
> **1. Core**
> 
> LLM 本身不是 Agent，但却是所有 Agent 的核心。既可以完成简单编排，也可以完成复杂推理。LLM 本身不具备工具、交互、记忆等能力，它仅依赖海量的训练数据进行响应。所以，Agent 的任务，就是给 LLM 搭配上其他需要的组件，让其发挥威力。
> 
> **2. Tool**
> 
> 这里说的 Tool 是广义上的工具，包括知识库、联网搜索、工具调用、任务编排等等，也就是上文所说的组件。这样，LLM 可以不局限于其训练的数据知识来执行一系列操作。
> 
> **3. Mem**
> 
> 要想 Agent 可以进化成战略规划、主动协助、自我进化的进阶形态，记忆功能则必不可失。但依据不同的 Agent 类型，Mem 模块的实现不一定是必须的，要依据不同业务进行轻量级或重量级的设计。

以上非常笼统地介绍了构成 Agent 组件/模块的分类，有很多没有提到的 key point，后文我们会一一介绍。当然，这些组件需要被一条线串起来，这条线就是 Agent 的推理决策过程。如何选择下一步、工具执行的结果，判断任务何时完成等 Task，就是这条线需要做的事情。

说到这里，我们其实已经可以发现，Agent 的设计和人类本身非常像，人的决策不就是这样吗？别人让我们做一件事情（或者我们自己），大脑思考如何完成，双手使用工具，眼睛盯住过程，大脑再次分析结果并做出下一步判断。这个系列篇章，就是在介绍和分享如何以 Agent 为主角，完成以上的过程。初步计划了以下几个专题：

1. Agentic 智能体设计模式
2. AI Agent 工程师岗位面试题详解
3. 大佬们文章的阅读心得
4. 从开源项目中收获的自己的理解

最后，非常推荐 Datawhale 的 [Hello Agent](https://github.com/datawhalechina/hello-agents) 项目，他可以很好的带领你从零到一的入门到 Agent 开发的工作中来。
